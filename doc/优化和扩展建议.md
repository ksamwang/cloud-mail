# Cloud Mail 优化和扩展建议

## 概述

本文档基于对 Cloud Mail 项目（`mail-worker` + `mail-vue`）的全面代码审查，梳理了当前存在的可优化点以及值得扩展的功能方向。所有建议均在 Cloudflare 生态内实施，保持零服务器成本的核心优势。

---

## 一、优化建议

### 1.1 密码哈希升级为 PBKDF2（优先级：P0）

**现状：** [`mail-worker/src/utils/crypto-utils.js`](../mail-worker/src/utils/crypto-utils.js) 仅使用单次 SHA-256 进行密码哈希，GPU 每秒可暴力尝试数百万次。

```js
// 当前实现
async genHashPassword(password, salt) {
    const data = encoder.encode(salt + password);
    const hashBuffer = await crypto.subtle.digest('SHA-256', data);
    return btoa(String.fromCharCode(...hashArray));
}
```

**建议：** 升级为 PBKDF2，使用 10 万次迭代。

```js
// 改进方案
async genHashPassword(password, salt) {
    const key = await crypto.subtle.importKey(
        'raw', encoder.encode(password),
        { name: 'PBKDF2' }, false, ['deriveBits']
    );
    const hashBuffer = await crypto.subtle.deriveBits(
        { name: 'PBKDF2', salt: encoder.encode(salt),
          iterations: 100000, hash: 'SHA-256' },
        key, 256
    );
    return btoa(String.fromCharCode(...new Uint8Array(hashBuffer)));
}
```

- **改动量：** ~15 行
- **兼容策略：** 登录时优先使用新算法验证，失败后回退旧算法，验证通过后自动 rehash
- **建议增加密码强度校验：** 禁止弱密码（纯数字、少于 8 位、与邮箱前缀相同等）

### 1.2 API 限流中间件（优先级：P0）

**现状：** 零限流保护，登录接口 `/login` 无任何频率限制，可被暴力破解。

**建议：** 基于 Cloudflare KV 实现令牌桶限流中间件。

```js
// mail-worker/src/hono/rate-limit.js
export function rateLimit({ window = 60, max = 60 } = {}) {
    return async (c, next) => {
        const ip = c.req.header('CF-Connecting-IP') || 'unknown';
        const key = `rate:${ip}:${c.req.path}`;
        const count = parseInt(await c.env.kv.get(key) || '0');
        if (count >= max) {
            throw new BizError('Too many requests', 429);
        }
        await c.env.kv.put(key, count + 1, { expirationTtl: window });
        await next();
    };
}

// 针对登录接口使用更严格的限制
app.post('/login', rateLimit({ window: 60, max: 5 }), loginHandler);
app.post('/register', rateLimit({ window: 3600, max: 3 }), registerHandler);
// 通用 API 使用宽松限制
app.use('/api/*', rateLimit({ window: 60, max: 60 }));
```

- **改动量：** ~40 行（新增文件 + 注册中间件）
- **收益：** 防止暴力破解、批量注册、API 滥用
- **注意：** `CF-Connecting-IP` 是 Cloudflare 提供的真实 IP header，无需自己解析

### 1.3 附件 Key 加入唯一标识防止冲突（优先级：P0）

**现状：** [`mail-worker/src/email/email.js`](../mail-worker/src/email/email.js) 附件 key 仅由 hash + 扩展名组成。

```js
// 当前：两封不同邮件的相同附件会产生 key 冲突
```

**建议：** 加入 emailId 或 uuid 保证唯一性。

```js
// 改进方案
attachment.key = `attachments/${emailId}/${uuidv4()}_${hash}${ext}`;
```

同时修改 [`mail-worker/src/service/att-service.js`](../mail-worker/src/service/att-service.js) 中 `saveSendAtt` 方法的 key 生成逻辑：

```js
// mail-worker/src/service/att-service.js line 155
att.key = `attachments/${emailId}/${uuidv4()}_`
```

- **改动量：** ~20 行（需要确认所有 key 构造点统一修改）
- **注意：** 旧格式 key 仍存在 R2/KV/S3 中，需保持兼容读取

### 1.4 统计查询优化 — 消除全表扫描（优先级：P1）

**现状：** [`mail-worker/src/dao/analysis-dao.js`](../mail-worker/src/dao/analysis-dao.js) 的 `numberCount` 方法对 email 表做全表 `SUM(CASE WHEN ...)` 扫描。邮件量超过 10 万条后每次请求响应变慢。

**建议 A（简单方案）：** 用 KV 缓存统计结果，Cron 定时刷新（当前已有但轮询周期可改）。

```js
// 在 scheduled 中增加统计增量更新
async function incrementStats(env, type, isDel) {
    const key = `stats:${type}:${isDel}`;
    const current = parseInt(await env.kv.get(key) || '0');
    await env.kv.put(key, current + 1);
}
```

**建议 B（根本方案）：** 创建 `stats` 计数器表，利用 D1 触发器自动维护。

```sql
CREATE TABLE IF NOT EXISTS stats (
    stat_key TEXT PRIMARY KEY,
    stat_value INTEGER NOT NULL DEFAULT 0
);

-- 插入新邮件时通过应用代码更新计数器
-- 物理删除时对应减少
```

- **改动量：** ~80 行
- **收益：** 统计查询从 O(n) 降为 O(1)

### 1.5 用户列表查询批处理优化（优先级：P1）

**现状：** [`mail-worker/src/service/user-service.js`](../mail-worker/src/service/user-service.js) 用户列表一次请求触发 7 个并行子查询（收件数、发件数、已删收件数、已删发件数、账号数、已删账号数、角色列表）。

**建议：** 将 7 次查询合并为 1 次 JOIN + GROUP BY 查询。

```sql
SELECT
    u.user_id,
    COUNT(CASE WHEN e.type = 0 AND e.is_del = 0 THEN 1 END) AS receive_count,
    COUNT(CASE WHEN e.type = 1 AND e.is_del = 0 THEN 1 END) AS send_count,
    COUNT(CASE WHEN e.type = 0 AND e.is_del = 1 THEN 1 END) AS del_receive_count,
    COUNT(CASE WHEN e.type = 1 AND e.is_del = 1 THEN 1 END) AS del_send_count,
    COUNT(DISTINCT CASE WHEN a.is_del = 0 THEN a.account_id END) AS account_count,
    COUNT(DISTINCT CASE WHEN a.is_del = 1 THEN a.account_id END) AS del_account_count
FROM user u
LEFT JOIN email e ON e.user_id = u.user_id
LEFT JOIN account a ON a.user_id = u.user_id
WHERE u.user_id IN (...)
GROUP BY u.user_id
```

- **改动量：** ~50 行
- **收益：** 用户列表页加载速度提升 40%+，大幅减少 D1 读取消耗

### 1.6 统一日志系统（优先级：P1）

**现状：** 36 处 `console.log/warn/error` 分散在 7 个文件中，无法按环境控制输出级别，生产环境可能泄露敏感信息。

**建议：** 新增统一日志工具模块。

```js
// mail-worker/src/utils/logger.js
const LEVELS = { DEBUG: 0, INFO: 1, WARN: 2, ERROR: 3, OFF: 4 };

export function createLogger(env) {
    const level = LEVELS[env.log_level] ?? LEVELS.INFO;

    return {
        debug(...args) { if (level <= LEVELS.DEBUG) console.debug('[DEBUG]', ...args); },
        info(...args)  { if (level <= LEVELS.INFO)  console.info('[INFO]', ...args); },
        warn(...args)  { if (level <= LEVELS.WARN)  console.warn('[WARN]', ...args); },
        error(...args) { if (level <= LEVELS.ERROR) console.error('[ERROR]', ...args); },
    };
}
```

在 `wrangler.toml` 中增加配置：

```toml
[vars]
log_level = "INFO"  # DEBUG | INFO | WARN | ERROR | OFF
```

- **改动量：** 新增 ~40 行 + 替换 36 处调用
- **收益：** 生产环境关闭 DEBUG 日志，错误排查可控

### 1.7 密码生成使用安全随机数（优先级：P2）

**现状：** [`mail-worker/src/utils/crypto-utils.js`](../mail-worker/src/utils/crypto-utils.js) 的 `genRandomPwd` 使用 `Math.random()`，可被预测。

```js
// 当前：不安全的随机
result += chars.charAt(Math.floor(Math.random() * chars.length));
```

**建议：** 改用 `crypto.getRandomValues`。

```js
genRandomPwd(length = 12) {  // 同时增加默认长度
    const chars = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789!@#$%^&*';
    const array = new Uint8Array(length);
    crypto.getRandomValues(array);
    return Array.from(array, b => chars[b % chars.length]).join('');
}
```

- **改动量：** ~5 行
- **收益：** API 批量创建用户时的密码不再可预测

### 2.1 邮件全文搜索 FTS5（推荐指数：⭐⭐⭐⭐⭐）

**现状：** 仅支持 `LIKE` 模糊匹配标题、发件人、收件人（[`email-service.js`](../mail-worker/src/service/email-service.js)），不支持搜索邮件正文。

**建议：** 使用 D1 内置的 FTS5 全文索引。

```sql
-- D1 Migration
CREATE VIRTUAL TABLE IF NOT EXISTS email_fts USING fts5(
    subject, content, text, send_email, to_email, code,
    content='email',
    content_rowid='email_id'
);

-- 触发器自动同步
CREATE TRIGGER IF NOT EXISTS email_ai AFTER INSERT ON email BEGIN
    INSERT INTO email_fts(rowid, subject, content, text, send_email, to_email, code)
    VALUES (new.email_id, new.subject, new.content, new.text, new.send_email, new.to_email, new.code);
END;

CREATE TRIGGER IF NOT EXISTS email_ad AFTER DELETE ON email BEGIN
    INSERT INTO email_fts(email_fts, rowid, subject, content, text, send_email, to_email, code)
    VALUES ('delete', old.email_id, old.subject, old.content, old.text, old.send_email, old.to_email, old.code);
END;

CREATE TRIGGER IF NOT EXISTS email_au AFTER UPDATE ON email BEGIN
    INSERT INTO email_fts(email_fts, rowid, subject, content, text, send_email, to_email, code)
    VALUES ('delete', old.email_id, old.subject, old.content, old.text, old.send_email, old.to_email, old.code);
    INSERT INTO email_fts(rowid, subject, content, text, send_email, to_email, code)
    VALUES (new.email_id, new.subject, new.content, new.text, new.send_email, new.to_email, new.code);
END;
```

```js
// 搜索 API
async searchEmail(c, keyword, userId) {
    const results = await c.env.db.prepare(`
        SELECT e.* FROM email e
        INNER JOIN email_fts fts ON e.email_id = fts.rowid
        WHERE email_fts MATCH ? AND e.user_id = ?
        ORDER BY rank LIMIT 50
    `).bind(keyword, userId).all();
    return results;
}
```

- **改动量：** 后端 ~100 行 + 数据库迁移 + 前端搜索栏 ~150 行
- **收益：** 用户感知最强的功能提升，从"基本搜不了"变为"毫秒级全文检索"

### 2.2 邮件会话视图 Thread View（推荐指数：⭐⭐⭐⭐⭐）

**现状：** 数据库已有 `inReplyTo`、`references`、`messageId` 字段记录回复关系（[`email-service.js`](../mail-worker/src/service/email-service.js)），但前端按时间平铺展示，无对话分组。

**建议：** 按 `messageId / inReplyTo` 组装对话树。

```js
// mail-worker/src/service/email-service.js
async threadView(c, userId, accountId) {
    const emails = await orm(c).select().from(email).where(
        and(eq(email.userId, userId), eq(email.accountId, accountId),
            eq(email.isDel, isDel.NORMAL), eq(email.type, emailConst.type.RECEIVE))
    ).orderBy(desc(email.createTime)).limit(200).all();

    // 构建 messageId -> children 映射
    const replyMap = {};
    for (const e of emails) {
        if (e.inReplyTo) {
            if (!replyMap[e.inReplyTo]) replyMap[e.inReplyTo] = [];
            replyMap[e.inReplyTo].push(e);
        }
    }

    // 找根邮件（没有 inReplyTo 或引用的邮件不在列表中）
    const roots = emails.filter(e =>
        !e.inReplyTo || !emails.find(p => p.messageId === e.inReplyTo)
    );

    return buildTrees(roots, replyMap);
}
```

前端使用递归组件渲染对话缩进。

- **改动量：** 后端 ~50 行 + 前端 ~300 行
- **收益：** 邮件体验质的飞跃，从"留言板"到"对话"

### 2.5 管理端批量创建邮箱（推荐指数：⭐⭐⭐⭐⭐）

**现状：** 管理员在后台只能逐个创建用户/邮箱，或者通过 `/public/addUser` API 批量导入。管理前端缺少可视化的批量创建入口。

**建议：** 在管理后台增加批量创建邮箱功能，支持：

1. **指定数量生成** — 输入数量 N，自动生成 N 个前缀 + 域名组合的邮箱
2. **密码策略** — 支持自定义统一密码，或随机生成安全密码
3. **一键复制** — 结果以表格展示，每行一个邮箱，提供复制按钮
4. **导出 TXT** — 每行格式为 `邮箱----密码`，方便分发

**后端新增 API：**

```js

app.post('/account/batchAdd', async (c) => {
    const params = await c.req.json();
    const result = await accountService.batchAdd(c, params);
    return c.json(result.ok(result));

```

```js
// mail-worker/src/service/account-service.js
async batchAdd(c, params) {
    const { prefix, domain, count, password, roleName } = params;

    if (!c.env.domain.includes(domain)) {
        throw new BizError(t('notEmailDomain'));
    }

    if (!password || password.length < 6) {
        throw new BizError(t('pwdMinLength'));
    }

    const results = [];
    const { salt, hash } = await cryptoUtils.hashPassword(password);

    for (let i = 0; i < count; i++) {
        // 生成唯一前缀：prefix + 随机数
        const suffix = generateUniqueSuffix(i, count);
        const email = `${prefix}${suffix}@${domain}`;

        // 检查是否已存在
        const existAccount = await accountService.selectByEmailIncludeDel(c, email);
        if (existAccount) continue;

        const userId = await userService.insert(c, {
            email,
            password: hash,
            salt,
            type: roleName || null
        });
        await accountService.insert(c, {
            userId: userId,
            email,
            name: emailUtils.getName(email)
        });
        await userService.updateUserInfo(c, userId, true);

        results.push({ email, password });
    }

    return results;
}

// 生成不重复的后缀
function generateUniqueSuffix(index, total) {
    const timestamp = Date.now().toString(36);
    const rand = Math.floor(crypto.getRandomValues(new Uint32Array(1))[0] % 10000);
    return `${timestamp}${rand}`.slice(0, 6);
}
```

### 2.6 阿里云 OSS 对象存储支持（推荐指数：⭐⭐⭐⭐⭐）

**现状：** 当前存储层通过 [`r2-service.js`](../mail-worker/src/service/r2-service.js) 的 `storageType()` 自动检测：

```js
// 当前逻辑：自动降级
if (bucket && endpoint && s3AccessKey && s3SecretKey) return 'S3';  // S3 优先
if (c.env.r2) return 'R2';                                          // R2 次之
return 'KV';                                                         // KV 兜底
```

无法显式指定存储类型，当一个 Worker 同时绑定 R2 又配置了 S3 兼容凭证时，无法选择使用 R2。

**建议：** 增加 `storage_type` 显式选择字段，新增阿里云 OSS 作为独立选项。OSS 天然兼容 S3 API，可直接复用现有 `s3-service.js` 的 `@aws-sdk/client-s3` 实现，无需引入额外 SDK。

**后端改动：**

**1. 新增常量 — [`entity-const.js`](../mail-worker/src/const/entity-const.js)**

```js
export const storageTypeConst = {
    KV: 'KV',
    R2: 'R2',
    S3: 'S3',
    OSS: 'OSS'
}
```

**2. 新增数据库字段 — [`entity/setting.js`](../mail-worker/src/entity/setting.js)**

```js
storageType: text('storage_type').default('').notNull()
```

**3. 修改存储检测逻辑 — [`r2-service.js`](../mail-worker/src/service/r2-service.js)**

```js
async storageType(c) {
    const setting = await settingService.query(c);
    // 显式选择优先
    if (setting.storageType === storageTypeConst.OSS) return 'OSS';
    if (setting.storageType === storageTypeConst.S3)  return 'S3';
    if (setting.storageType === storageTypeConst.R2)  return 'R2';
    if (setting.storageType === storageTypeConst.KV)  return 'KV';

    // 向后兼容：未设置时沿用旧逻辑自动检测
    if (!!(setting.bucket && setting.endpoint && setting.s3AccessKey && setting.s3SecretKey)) return 'S3';
    if (c.env.r2) return 'R2';
    return 'KV';
}
```

`putObj` / `getObj` / `delete` 方法中 OSS 走现有 S3 分支即可：

```js
// OSS 复用 S3 路径
if (storageType === 'S3' || storageType === 'OSS') {
    await s3Service.putObj(c, key, content, metadata);
}
```

`get()` 方法已对 `s3AccessKey` / `s3SecretKey` 做掩码处理，OSS 复用相同字段，无需额外改动。

## 四、注意事项

1. **D1 配额限制：** Cloudflare D1 免费版每月 500 万次读取 / 10 万次写入。新增功能时需评估额外查询量，FTS5 搜索和统计优化反而能减少 D1 消耗。
2. **批量创建限制：** 单次最多 100 个邮箱，防止单次请求导致 D1 写入配额耗尽。批量创建生成的密码若为随机模式，务必在结果页展示完毕前阻止页面关闭（可用 `beforeunload` 事件）。
3. **OSS S3 兼容模式：** 阿里云 OSS 的 S3 兼容模式经过充分测试，`PutObject` / `GetObject` / `DeleteObjects` 均可正常工作。需注意 `forcePathStyle` 建议设为 `true`，`region` 格式为 `oss-{region}`。
4. **KV 写入限制：** 免费版每日 1000 次写入。当前设置缓存、限流计数均涉及 KV 写操作，需要合并写入和优化 TTL。
5. **向后兼容：** 密码升级、附件 key 改造都需要兼容存量数据，不能上线就破坏现有功能。
6. **文档维护：** 随着新功能上线，同步更新 [`README.md`](../README.md) 和 [在线文档](https://doc.skymail.ink)。
